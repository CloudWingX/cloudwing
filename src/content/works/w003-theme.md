## 为什么要改

亮色主题看起来"干净"，实际用起来有两个真问题：

- **刺眼**：整页 **62.4% 的像素亮度 ≥ 0.94**（均值 0.914）—— 几乎整屏都是近白。
- **看不清**：三级文字（小节标题、日期、编号、页脚等 **32 处**）用的 `--ink-3` 对玻璃卡实测只有 **2.49:1**，远低于 WCAG AA 小字要求的 4.5:1。

这两条都不是"感觉"，是先量出来的：截图统计亮度分位数，再逐节点算"前景 vs 实际合成背景"的对比度。

## 改了什么

| 指标 | 改前 | 改后 |
|---|---|---|
| 近白像素（亮度 ≥0.94） | 62.4% | **56.2%** |
| 页面均值亮度 | 0.914 | **0.900** |
| 不达标文字（WCAG AA） | **38 处** | **0 处** |
| 三级文字对比度 | 2.49:1 | **4.87:1**（玻璃上 5.56:1） |
| 暗色三级文字 | 3.93:1 | **4.66:1** |

- 页面底色 `#f4f4f5 → #e9ebee`，玻璃面板同步压深；**内容卡保持近白**，靠层次而不是靠整体发白撑版面。
- `--ink-3` `#9a9ca3 → #63656d`，`--ink-2` `#55575e → #45474e`。
- 粒子背景改为跟随主题（浅色下更淡更少，不再像一层浮尘）。
- 边框加粗加深：`--line-1` 1.32:1 → 2.0:1、`--line-2` 1.84:1 → 3.5:1（非文字 UI 的可见性门槛是 3:1），并区分"内容卡 / 交互控件 / 小胶囊"三档粗细。

## 踩到的坑

**浅色页底色改了却不生效。** `global.css` 里 `body` 的背景被 `motion.css` 的一条规则**整条覆盖**——也就是说浅色底色的真实取值一直藏在 `motion.css`，只改 `global.css` 的变量不会改变任何渲染结果。我是先改完、截图发现**均值与改前完全一致**才察觉的。

**Blink 会把 `1.5px` 向下取整成 `1px`**（实测 devicePixelRatio 1 与 3 都是 1px），第一版"加粗"其实没生效，后来统一改成 `2px`。

**Astro 页面/组件里的作用域样式优先级高于全局 CSS**：`Header.astro` 等 6 个文件里写死的 `1px solid` 会把全局加粗局部盖掉，共 15 处已全部改走令牌。

## 留下的验证工具

- `scripts/contrast-audit.mjs [url] [light|dark]` —— 逐节点 WCAG 对比度审计（两种主题）。
- `scripts/imgstats.mjs` / `imgpix.mjs` —— 亮度分位数、过曝占比、四角采点。
- `scripts/border-check.mjs` / `card-separation.mjs` —— 直接量"实际生效的边框宽度/颜色"与"卡面 vs 页面底色分离度"。

## 结果

亮色与暗色两套主题现在都是 **0 处文字不达标**；配色仍是黑白灰 + 玻璃，没有引入新颜色。
